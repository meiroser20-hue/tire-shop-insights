# Tire Shop Insights

פרומפט Lovable — אפליקציית ניהול פנצ'ריית ברכת הדרך

מה בונים

אפליקציית ניהול עסקית לפנצ'ריית משאיות בנתניה. הנתונים כבר קיימים ב-Supabase ומתעדכנים אוטומטית מ-Priority ERP כל 3 דקות. האפליקציה קוראת בלבד — היא לא כותבת לבסיס הנתונים.

המשתמש העיקרי הוא בעל העסק, שפותח מהנייד פעמיים ביום. הוא לא אנליסט. כל מסך צריך לענות על שאלה אחת בשנייה הראשונה.

עברית מלאה, RTL, מובייל-first עם התאמה מושלמת לדסקטופ.

מספר ההכנסה

ממורכז, 50px, --coral-900. מתחתיו צ'יפ ירוק/אדום עם אחוז השינוי מהתקופה המקבילה.

גריד 2×3. כל כרטיס: רקע rgba(255,255,255,.78), פינות 16px. תווית 11px + מספר 23px + שורת שינוי 10.5px (ירוק למעלה, אדום למטה).

איזונים — יחידות

סקשן: תנועה לפי שעה

עמודות. שעת השיא ב---coral-600, שאר השעות בגוונים בהירים יותר לפי גובה. מתחת: שעת השיא 15:00 · 13:00 שקטה

מקור: v_sales_by_hour

סקשן: כבד מול פרטי

דונאט (conic-gradient) עם סכום ומספר רכבים במרכז. לצידו מקרא: משא / פרטי / מסחרי — אחוז מההכנסה + מספר רכבים.

מקור: v_sales מקובץ לפי vehicle_class

סקשן: מה נמכר

פסים אופקיים ממוינים לפי הכנסה: צמיגים, תיקון תקר, איזון, פירוק והרכבה, כיול.

מקור: v_service_mix

סקשן: לקוחות מובילים

שלוש שורות. עיגול עם ראשי תיבות (מסגרת 2px בקורל), שם, ביקורים ורכבים, סכום. אייקון מדליה למקום הראשון (ti-medal, זהב).

מקור: v_customers_unified ממוין לפי lifetime_net

סקשן: מידות מובילות

צ'יפים: מידה, יחידות, סכום. שלוש הראשונות ברקע --coral-100.

סקשן: רכבים אחרונים

עיגול ראשי תיבות, שם לקוח, שעה + מספר רכב + מה נעשה, סכום + סוג רכב. תווית חוזר ×N ירוקה ליד השם כשהלקוח חוזר.

מקור: v_sales + v_customers_unified

סקשן: כספים

ארבעה כרטיסים צבעוניים בגריד 2×2:

חייבים לי — --teal-bg / --teal-fg

אני חייב — --violet-bg / --violet-fg

בפיגור — --amber-bg / --amber-fg

צפוי להיכנס השבוע — --blue-bg / --blue-fg

סקשן: מלאי

שלושה כרטיסים: ייגמר השבוע · צמיגים במלאי · מלאי מת. מתחת: שורת פירוט על הפריט הדחוף ביותר.

מקור: v_stock_current, v_dead_stock, v_stock_forecast

סקשן אחרון: תובנות

משפטים קצרים מ-v_insights. מוצג רק אם יש שורות. בלי כותרת "אין תובנות".

מסך 3 — לקוחות

רשימה

חיפוש (שם, טלפון, מספר רכב) + סינון:

הכל · עסקי · פרטי · חוזר · חייב · לא חזר


כל שורה: עיגול ראשי תיבות, שם, תווית סוג, ביקורים, סכום מצטבר.

לקוחות מובילים

לפי הכנסה / תדירות / ותק — מתג.

לקוחות שנעלמו

is_dormant = true ו-visits >= 2. עם כפתור חיוג וכפתור וואטסאפ.

מסך 4 — מלאי

שלוש התראות: ייגמר השבוע · מלאי מת · שווי תקוע. לחיצה → רשימה מסוננת

טבלה: מידה, מותג, יתרה, תנועה אחרונה, קצב, תחזית

חיפוש לפי מידה, מותג, מק"ט

גרף מגמה לפריט בודד

מקורות: v_stock_current, v_dead_stock, v_stock_forecast, partbal_snapshots

מסך 5 — כספים

חייבים לי + גיול: 30 / 60 / 90 / 90+

אני חייב לספקים + מועדי תשלום

תזרים צפוי — כניסות מול יציאות

חשבוניות שלא הופקו — תעודות עם invoiced = 'N'. סקשן מרכזי

רווחיות — מרווח לפי מידה, מותג, שירות. מוצג רק אם יש נתוני רכש, אחרת:

אין עדיין נתוני עלות רווחיות תוצג ברגע שיוזנו חשבוניות ספק בפריוריטי

רכש לפי ספק

מקורות: customer_obligo, purchase_invoices, invoices, delivery_docs

מסך 6 — דוחות

דוח מכירות · מלאי · גבייה · לקוחות · רווחיות

בחירת טווח תאריכים + פילטרים

הרשאות

טבלת profiles ב-schema public:

id uuid references auth.users, full_name text, role text


תפקידים: owner (הכל) · office (בלי רווחיות ועלויות)

office רואה בכספים רק גבייה.

מצבי טעינה ושגיאה

טעינה: שלד אפור (skeleton), לא ספינר

ריק: משפט שמסביר מה יקרה, לא "אין נתונים"

שגיאה: "לא הצלחנו לטעון. נסה שוב" + כפתור. בלי מונחים טכניים

מה לא לעשות

לא לכתוב לבסיס הנתונים — קריאה בלבד

לא להמציא נתונים כשאין. להציג מצב ריק

לא לערבב amount_net עם amount_gross באותו חישוב

לא להשתמש ב-schema public לנתונים עסקיים

סדר בנייה

Auth + מסך התחברות + ניווט + חיבור Supabase
